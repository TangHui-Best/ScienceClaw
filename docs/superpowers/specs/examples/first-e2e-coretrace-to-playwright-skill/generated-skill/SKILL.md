# 跨系统采购订单验收登记

## 适用场景

根据输入条件在系统 A 查询唯一采购订单，提取其业务字段，打开该订单对应的系统 B 验收登记页，并在验收登记 iframe 内填写和提交表单。

## 输入

| 参数 | 说明 | 必填 |
| --- | --- | --- |
| `system_a_url` | 系统 A 采购订单查询页地址 | 是 |
| `query.business_type` | 业务类型 | 是 |
| `query.date_from` | 订单日期起始日，格式 `YYYY-MM-DD` | 是 |
| `query.date_to` | 订单日期结束日，格式 `YYYY-MM-DD` | 是 |
| `query.supplier_name` | 供应商名称 | 是 |
| `query.order_no` | 订单编号，也是目标行的业务主键 | 是 |

## 阶段一：浏览器流程

1. 打开系统 A 采购订单查询页。
2. 通过自定义下拉框、日期范围、供应商名称和订单编号设置查询条件。
3. 点击图标查询按钮。
4. 通过受控 Agent 在查询结果中找到订单编号匹配的唯一行，提取 `采购订单` 业务对象。
5. 在目标行点击“发起验收”，捕获本次点击产生的新页面。
6. 通过稳定 iframe 身份进入系统 B 验收表单。
7. 使用 `采购订单.*` 变量填写来源订单号、供应商、合同号、验收金额、币种和订单日期。
8. 填写固定业务说明“自动创建”，勾选信息确认，保存并确认提交。
9. 提取页面上的保存成功信息为声明输出 `acceptance_result`。

## 阶段二：数据处理规则

本 Skill 没有阶段二数据处理规则。采购订单字段在浏览器阶段内直接跨页面传递。

## 阶段三：通知

本 Skill 没有阶段三通知配置。

## 输出

| 输出 | 来源 | 说明 |
| --- | --- | --- |
| `acceptance_result` | 业务变量 `验收结果` | 页面显示的辅助成功信息；正式 E2E 结果仍由后端 Oracle 判定 |

## 失败边界

- 查询结果无法唯一确定目标订单时失败；
- 采购订单提取结果缺少声明字段时失败；
- 新页面未由目标行点击产生时失败；
- iframe 或任一目标控件无法按声明 Locator 解析时失败；
- 任一变量在消费前不存在时失败，不回退到录制值；
- 页面显示成功不能替代后端 Oracle 对已保存业务数据的验证。
